## 2. 설계 대비 달라진 점

- **스레딩**: 설계 문서 8.4는 "봇마다 Actor"였지만, 구현은 **엔진 전체를 단일 이벤트 루프**로 직렬화했습니다
  (시세·주문 이벤트·사용자 명령·타이머 → 하나의 `Channel<Action>`). 수십 종목 규모에서는 성능 여유가 충분하고,
  봇·리스크·주문 추적 사이에 락이 전혀 없어 경쟁 조건이 원천적으로 사라집니다. 주문 전송(REST)과 스캐너만 별도 스레드입니다.
- **웹소켓 연결 1개**: 계정당 2개 제한 중 1개만 사용 (봇 종목 체결+호가, 스캐너 상위 후보 체결, 내 주문 이벤트 → 95토픽 예산).
  나머지 1개는 토스 앱/다른 도구용 여유로 남겼습니다.
- **기본 리스크**: 거래당 리스크 기본값을 0.5% → **0.2%** 로 낮췄습니다. 봇 손실 한도(최대 투입금의 2%)와 맞추기 위해서입니다.

## 4. 실제 토스 계정으로 확인해야 하는 것 (★)

개발 환경에서 `developers.tossinvest.com` 접근이 막혀, API 형식은 **비공식 SDK(toss-go v0.3.0) 소스**를 기준으로 구현했습니다.
`TossTrading.Cli check` 로 아래를 먼저 확인하세요.

1. 토큰 발급 형식 (`POST /oauth2/token`, form-urlencoded) — `check` 1단계
2. 응답 봉투 `{"result": ...}` 와 필드명 — `check` 의 현재가/호가/분봉/랭킹/종목정보 단계
3. 계좌 헤더 `X-Tossinvest-Account` — `check` 의 매수가능금액/보유종목 단계
4. 웹소켓 선언 형식과 프레임 — `check` 마지막 15초 수신 (장 시간에 실행)
5. 주문 API — **반드시 소액·지정가·체결 안 될 가격**으로 1회 실험 후 취소 (앱의 실전 모드 전에)
6. 호출 한도 수치 — 응답 헤더 `X-RateLimit-Limit` 을 자동 반영하지만 초기값은 `TossOptions` 에서 조정
7. mTLS 인증서 필요 여부 — 필요하다면 `TossRestClient` 의 `HttpClient` 에 클라이언트 인증서를 추가해야 함

형식이 다르면 수정 지점은 `src/TossTrading.Toss/Dtos.cs`(필드명)와 `TossRestClient.cs`/`TossStreamClient.cs` 두 곳으로 한정됩니다.

## 6. 종가매매 (종가 베팅 → 익일 매도)

프리셋 **"종가베팅 (익일 매도)"** 또는 봇 설정 ⑤에서 사용합니다.

**진입 (`ClosingBetSignal`, 기본 15:00~15:19, 하루 1회)** — 모두 만족 시 신호
1. 당일 등락률 +3% ~ +20% (강세지만 상한가 추격은 아님)
2. 당일 고저 범위 상단 75% 이상에서 거래 (고가 부근 마감)
3. VWAP 위, 체결강도 100 이상(데이터 있을 때)
4. 최근 30분간 밀리지 않음
5. 상한가 3% 이내 제외

**보유·청산 규칙 (`HoldOvernight`)**
- 당일 강제청산(15:10)·타임스탑을 쓰지 않는다. 신규 진입은 15:20(종가 단일가 시작) 전까지만.
- 진입 당일에는 **손절만** 적용 (익일 갭을 노리는 전략이므로 당일 익절·트레일링은 하지 않음).
- 정규장 접속매매(09:00~15:20)에서만 청산 판단 — 동시호가·NXT 시간외의 얇은 체결로 손절되지 않도록.
- 익일 청산 방식
  - **시초 매도**: 익일 첫 체결 직후 전량 시장가
  - **관리**(기본): 손절·분할익절·트레일링·본절을 적용하고, 익일 청산 시각(기본 10:00)에 남은 수량 매도
- 프리셋 기본값: 손절 3%, 1차 익절 +2%(50%), 최종 +5%, 트레일링 +2.5% 이후 고점 대비 1.5%, 거래당 리스크 0.2%, 1회 진입

**재시작 후 이어서 관리 (토스 데이터일 때)**
- 봇 상태와 모의계좌(예수금·보유)를 `%LocalAppData%\TossTrading\state\` 에 2초마다(변경 시) 저장
  (`bots_paper.json` / `bots_live.json`, `paper_account.json`).
- 다음 날 시작하면 보유 중인 봇만 복원해 바로 청산 관리를 시작하고, 당일 통계는 새로 시작한다. 같은 날 재시작하면 모든 봇을 복원.
- 실전 모드는 복원 시 실제 계좌 잔고와 대조해 수량을 맞춘다. 계좌에 남은 미체결 주문은 경고만 한다.
- 설정 → 비용·기타 → **모의계좌 초기화**로 저장된 모의 상태를 지울 수 있다.
- 시뮬레이션 시장은 종목이 매번 새로 만들어지므로 저장하지 않는다. 대신 **시뮬레이션 시작 시각**을 14:30 등으로 두면 종가 진입까지는 바로 연습할 수 있다
  (익일 청산은 토스 실시간 + 모의 주문으로 확인).

**주의**
- 밤사이 악재·시장 급락으로 **익일 시가가 손절가보다 훨씬 낮게 시작할 수 있다**. 손절은 시가 이후에 나가므로 손실이 설정 %보다 커질 수 있다 → 투입금·리스크 %를 보수적으로.
- 종가매매 효과는 시장 국면에 따라 크게 달라진다. 반드시 모의로 20거래일 이상 검증한 뒤 소액으로.
- 헤드리스 확인: `dotnet run --project src\TossTrading.Cli -- sim 70 60 closing` (14:40 시작, 종가베팅 봇 자동 운용)

### 6-1. 종가매매 후보 검색 (스캐너 "종가매매 후보" 모드)

스캐너 위 **모드**를 `종가매매 후보`로 바꾸면:
- 필터: 등락률은 종가매매 범위(기본 +3~20%)로, RVOL 조건은 빼고(거래대금으로 유동성 판단) 나머지(가격·틱비용·경고·보통주)는 동일.
- **후보 전체**의 당일 1분봉을 조회해 고저 범위 위치·VWAP·30분 추세를 계산 (실시간 구독 상위 20개에 한정되지 않음).
  호출 한도를 위해 한 번 스캔에 8종목씩(`ClosingBarsPerCycle`), 60초 지난 것부터 갱신 → 후보 40개 기준 약 25초면 전체가 채워진다.
  실시간 구독 중인 종목은 실시간 값(체결강도 포함)을 우선 사용.
- 각 종목에 봇 매수 조건과 같은 기준의 **조건표**: `등락✔ 고가권✔ VWAP✔ 30분✖ 강도? 상한가✔` (✔ 통과 ✖ 실패 ? 데이터 없음)
- 정렬: 조건 모두 통과(태그 `종가후보`, 굵게) → 통과 개수 → 종가 점수
  (고가권 30% · VWAP 20% · 30분 추세 20% · 거래대금 15% · 체결강도 15%, 실패 항목당 −10점)
- 모드를 바꾸면 봇 추가 프리셋이 자동으로 "종가베팅 (익일 매도)"로 바뀐다.
- 체결강도는 실시간 구독 종목만 계산되므로 하위 후보는 `강도?` 로 표시된다. 봇을 추가하면 해당 종목을 구독하므로 봇이 매수 전 체결강도까지 다시 확인한다.

## 7. 알고리즘 개선용 매매 로그와 성과 분석

목표: "어떤 조건에서 들어간 거래가 돈을 벌었나 / 손절·익절 폭이 맞나 / 놓친 기회는 없나"를 **데이터로** 답할 수 있게 한다.

### 7-1. 저장되는 기록 — `%LocalAppData%\TossTrading\journal\analysis_yyyyMMdd.jsonl`
한 줄에 한 건, `{"kind": ..., "data": {...}}` 형식 (한글 그대로 저장 → 메모장에서도 읽힘).

| kind | 언제 | 주요 내용 |
|---|---|---|
| `trade` | 거래 종료(전량 매도) 시 | 진입 근거, **진입 시 시장 상황**(등락률·VWAP 이격·당일 범위 위치·체결강도·ATR%·거래량 배수·스프레드·장 시작 후 분), 결정가 대비 **진입 슬리피지**, 초기 손절·손절 거리%, **MFE/MAE**(보유 중 최고/최저), 매도 체결 내역(분할 익절 포함, 분류·기준가·체결가), **청산 슬리피지**, 총손익·비용·순손익·R, 보유 시간, 익일 보유 여부, **당시 봇 설정 전체**, 청산 시 시장 상황 |
| `signal` | 전략 신호 발생 시 | 결과(진입 / 차단+사유 / 승인대기 / 시간외 / 진입불가), 신호 근거, 시장 상황. 같은 결과가 반복되면 60초에 1회만 |
| `decision` | 반자동 신호 처리 시 | 승인→진입, 승인→차단, 거절, 만료(60초/가격 이탈) |
| `followup` | 청산·미진입 신호 이후 | 5/15/30/60분 후 가격, 30·60분 최고/최저, 장 마감가 → "손절 후 반등했나", "익절 후 더 갔나", "안 들어간 신호는 어땠나" |

- 진행 중인 거래의 분석 상태는 봇 상태(`bots_*.json`)와 함께 저장되어 **종가매매 익일 보유/재시작 후에도 이어서** 기록된다.
- 추적 중인 종목은 봇을 지워도 60분간 체결 구독을 유지한다 (구독 한도 내).
- 기존 `trades_yyyyMMdd.jsonl`(요약)과 `logs\log_yyyyMMdd.txt`(텍스트 로그)는 그대로 유지.

### 7-2. 분석 — 앱 [📊 성과 분석] 또는 CLI `report`
- 기간(오늘/5/30/90일/전체), 데이터(전체/토스/시뮬) 필터.
- 리포트: 요약(승률·기대값·손익비·PF·평균 R·최대 연속 손실), 전략별, 청산 사유별, 진입 시간대별, 진입 조건 구간별(등락률·VWAP 이격·범위 위치·체결강도·거래량 배수·스프레드), MFE/MAE 점검, 청산 후 흐름, 슬리피지, 신호 처리 결과.
- **개선 제안** (구간당 5건 이상일 때만): 예)
  - 손실 거래 다수가 한때 +1R → 본절 이동을 앞당기거나 분할 익절 확대
  - 이익 거래의 MAE 90% 지점이 손절 거리보다 훨씬 작음 → 손절 폭 축소 검토
  - 손절 후 60분 안에 매수가 회복이 잦음 → 손절이 너무 타이트 / 구조적 손절 사용
  - 익절 후 +2% 이상 추가 상승이 잦음 → 목표 상향·트레일링 연장
  - 특정 조건 구간의 기대값이 음수 → 진입 필터로 제외
  - 진입 슬리피지 과다 → 슬리피지 틱 축소, 스프레드 넓은 종목 제외
- [리포트·CSV 저장] → `reports\report_*.md`, `trades_*.csv`, `signals_*.csv` (UTF-8 BOM, 엑셀에서 바로 열림) → 피벗 테이블로 추가 분석.

```
dotnet run --project src/TossTrading.Cli -- report 30                 # 최근 30일, 기본 데이터 폴더
dotnet run --project src/TossTrading.Cli -- report 5 --source toss    # 토스 실데이터만
dotnet run --project src/TossTrading.Cli -- sim 120 120 --data .\simdata   # 시뮬 결과도 기록해 분석해볼 수 있음
```

### 7-3. 개선 절차 권장
1. 모의투자로 최소 30~50건 이상 쌓는다 (시뮬레이션 데이터는 토스 실데이터와 분리해서 볼 것).
2. 리포트의 제안 중 **하나만** 골라 설정(프리셋)을 바꾼다 — 기록에 당시 설정이 함께 저장되므로 전후 비교 가능.
3. 같은 기간 이상 다시 돌린 뒤 전략/설정별 기대값·PF를 비교한다. 표본이 적을 때의 차이는 우연일 수 있다.

## 8. 자동 운용 (종목 자동 선정 → 단타 → 종가매매 자동 전환)

메인 화면 **[🤖 자동 운용]** 체크 → 엔진이 시간대별로 종목 선정·봇 생성·정리를 모두 자동으로 한다 (`Engine/Automation/AutoPilot.cs`).

| 시각 (기본값) | 동작 |
|---|---|
| ~09:05 | 대기. 전날 종가 보유분은 각 봇이 익일 청산 규칙대로 매도 |
| 09:05 ~ 14:30 | 스캐너 **단타 모드**. 점수 50 이상 상위 종목으로 **단타 봇 최대 3개** (완전자동). 10:00 전에는 "ORB 표준", 이후 "VWAP 눌림 표준" 프리셋 |
| 〃 | 봇이 끝나면(목표 달성·손실 한도·진입 소진) 목록에서 빼고 **다른 종목으로 채움**. 30분간 진입이 없고 상위 후보에서 밀려난 봇도 교체. 같은 날 같은 종목은 다시 고르지 않음 |
| 14:30 | 단타 신규 진입 마감 (보유분은 계속 관리) |
| 14:40 | 스캐너 → **종가매매 후보 모드** (분봉 수집 시간 확보) |
| 14:50 | **단타 보유분 전량 정리** (종가 자금 확보) |
| 14:55 ~ 15:15 | 종가 조건을 **모두 통과**한 상위 종목으로 **종가베팅 봇 최대 2개**. 조건에서 3회 연속 탈락한 미진입 봇은 교체 |
| 15:00 ~ 15:19 | 종가베팅 전략이 조건을 다시 확인하고 매수 |
| 15:20 이후 | 매수 못 한 종가 봇 정리. 보유분은 다음 날 매도 후 자동 정리 |

- 킬스위치·일 손실 한도·연속 손실 쿨다운 중에는 **새 종목을 고르지 않는다** (기존 봇의 청산 관리는 계속).
- 직접 추가한 봇은 건드리지 않는다. 봇 목록 "구분" 열: 🤖 단타 / 🤖 종가 / 수동.
- 자동 운용을 끄면 새로 고르지 않고 스캐너 모드는 수동 설정으로 돌아간다. 이미 만든 봇은 각자 규칙대로 계속 관리된다.
- 설정: [설정 → 자동 운용] (시각, 봇 수, 최소 점수, 프리셋, 교체 시간, 종가 조건 최소 통과 수).
- 익일 보유 종목도 [리스크 → 동시 보유 한도](기본 4)에 포함된다. 오전에는 (전날 종가 보유 + 단타)가 한도를 넘으면 일부 단타 진입이 막힐 수 있다.
- CLI 확인: `dotnet run --project src/TossTrading.Cli -- sim 240 120 auto` (가상 09:00~15:30 하루 전체).

## 9. 백테스트 (기간을 정해 과거 데이터로 자동 운용 재생)

메인 화면 **[📈 백테스트]** → 기간·데이터·시작 자금 → [▶ 실행]. CLI: `backtest 2026-08-01 2026-08-31 --source toss`.

**구조** (`Engine/Backtest/`)
- `BacktestRunner`: 실매매와 **같은 TradingEngine**(자동 운용·봇·리스크·모의체결·분석 기록)을 가상 시계로 돌린다. 매 단계 `SettleAsync`로 주문·이벤트 처리가 끝날 때까지 기다려 결과가 매번 같다(결정적).
- `ReplayMarket`: 1분봉을 15초 간격 4개 체결로 분해 (양봉 시가→저가→고가→종가, 음봉 시가→고가→저가→종가 — 손절이 먼저 걸리는 보수적 경로). 호가는 1틱 스프레드로 합성. 순위·분봉·일봉 조회는 **그 시각까지의 데이터만** 돌려준다 (미래 참조 없음). 스캐너는 실시간과 같은 `ScanOnceAsync`를 1분마다 실행.
- 날짜별 종목 선별: 그날 일봉 **고가** 기준 등락률 ≥ 하한, 거래대금 ≥ 기준의 30% (장중 후보가 될 수 있었던 필요조건) → 거래대금 상위 N개 + 전날부터 보유 중인 종목.
- 데이터: `TossHistoryProvider`(토스 `candles` API, `before` 페이지 조회) → `CachedHistoryProvider`(`%LocalAppData%\TossTrading\history\`, 지난 날짜는 다시 조회 안 함). `SyntheticHistoryProvider`는 API 키 없이 동작 확인용 가상 데이터(무작위라 전략 성과 판단에는 쓰지 말 것).
- 결과: `backtests\<실행시각>\` 에 `report.md`(요약·전략별·일별·거래 내역), `trades.csv`, `daily.csv`, `analysis.md`([성과 분석]과 같은 진입조건·MFE/MAE·개선 제안), `journal\`, `logs\`.

**한계** (리포트에도 표시)
- 과거 순위 API가 없어 **현재 상위 종목 + 추가 종목**만 대상 (생존 편향 가능).
- 토스가 몇 달 전까지의 1분봉을 주는지는 실제 계정으로 확인 필요. 없으면 그날은 "분봉 데이터 없음"으로 건너뛴다.
- 분봉 내부 체결 순서·호가 잔량·체결강도·VI·투자경고는 재현하지 않는다.

**함께 고친 것**: 엔진을 밤새 켜 두면 종목별 당일 통계(VWAP·고저·분봉)가 다음 날로 넘어가던 문제 → 날짜가 바뀌면 `SymbolContext.ResetSession()`으로 초기화하고 상하한가·전일종가를 다시 채운다.
